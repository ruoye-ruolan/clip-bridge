# macOS Toolkit Source Guide

Last updated: 2026-09-30.

This directory contains ClipBridge's Python orchestration and native Swift clipboard helpers. It retains the `prototype/macos/` path while the source toolkit is being prepared for a release. The supported repository entry point is [`../../clipbridge`](../../clipbridge).

For configuration and day-to-day commands, read the [user guide](../../docs/usage.md). Product and release decisions belong in the [planning document](../../docs/planning/product-direction-and-distribution.md).

## Source Layout

| File | Responsibility |
| --- | --- |
| `cli.py` | Parse commands, offer optional guided setup/diagnostics, run the foreground monitor and display logs |
| `configuration.py` | Validate JSON settings, discover SSH alias hints, check remote destinations and save configuration atomically |
| `service.py` | Manage launchd start/restart/stop/status, serialize service operations and prevent duplicate startup |
| `monitor_control.py` | Exchange private, instance-specific foreground handoff requests and wait for the monitor lock |
| `auto_upload.py` | Detect matching SSH processes, process clipboard events, serialize uploads and retain failed files |
| `swift/clipboard-watch.swift` | Poll pasteboard changes and capture supported image data as PNG |
| `swift/clipboard-path.swift` | Check the pasteboard change count before writing the uploaded file path |
| `config.example.json` | Placeholder configuration for users to copy and edit |
| `Makefile` | Compile helpers and run tests |
| `tests/` | Python unit/process tests and Swift pasteboard integration checks |

Generated helpers are stored in ignored `build/`. User settings normally live outside the checkout at `~/.config/clipbridge/config.json`; the ignored local `config.json` remains a migration fallback. LaunchAgent files are generated by the service module rather than maintained as hand-edited templates.

## Execution Flow

1. The root entry point imports `cli.py`. `run` builds helpers and executes the monitor with `--foreground`; `start` manages its launchd job.
2. The monitor loads a required SSH alias and absolute remote directory, acquires `watcher.lock`, and registers its instance metadata.
3. The Swift watcher baselines the clipboard and emits changes. Eligible image events are captured only when a matching SSH session is detected.
4. A single-worker executor rechecks the session, stages the image, creates the remote directory if needed, and transfers through system SSH/SCP.
5. After transfer, the path helper compares change counts before updating the clipboard. Logs record the destination even if newer clipboard content is preserved.

The monitor keeps its lock through queued-upload draining. On a cooperative foreground handoff it stops reading new events, terminates the watcher and drains work before releasing the lock. Interrupted executor shutdown retains the lock through interpreter exit so a second uploader cannot overlap unfinished work.

## Build and Development Commands

Run from the repository root on macOS with Python 3.9+, `swiftc` and `make` available:

```sh
make -C prototype/macos build
make -C prototype/macos test
```

| Command | Purpose |
| --- | --- |
| `make -C prototype/macos test-python` | Run standard-library `unittest` discovery |
| `make -C prototype/macos test-swift` | Compile and run the private-pasteboard integration test |
| `make -C prototype/macos clean` | Remove generated helpers and test binaries |
| `make -C prototype/macos build SWIFTC=/path/to/swiftc` | Select a Swift compiler |
| `make -C prototype/macos test-python PYTHON=/path/to/python3` | Select a Python interpreter |
| `git diff --check` | Check tracked changes for whitespace errors |

`make configure`, `make doctor` and `make run` in this directory are convenience wrappers for the CLI. Unlike build/test targets, these can check a real SSH destination or start real monitoring. They are not automated validation steps.

No third-party Python packages, formatter, linter or CI workflow is configured. Follow [Repository Guidelines](../../AGENTS.md) for contribution conventions.

## Test Boundaries

- Configuration and CLI tests cover validation, private/atomic saves, legacy defaults, failed setup and configuration repair.
- Upload tests mock subprocess calls to check offline skipping, stale captures, failure retention and path-copy conditions.
- Service tests mock launchctl/build commands for repeated startup, restart, conflicting monitors, failed startup and cancellation cleanup.
- Handoff and lock-lifetime tests use temporary directories and harmless subprocesses, including interrupted upload draining. They do not start launchd services or the real clipboard watcher.
- The Swift integration test uses a private named pasteboard to verify image capture and stale-image rejection. It leaves the general clipboard untouched.

Python tests have been exercised with Python 3.9 and 3.14. Swift helper checks have run with Swift 6.4 on macOS 27.0.1, Apple silicon. These checks do not establish compatibility with all macOS releases or Intel Macs.

Repeated `start` has also been checked against an already running local background instance, preserving its PID. Full real-host transfer, foreground-to-launchd transition and another-machine installation remain release-validation work.

## Implementation Boundaries

Preserve the distinction between current behavior and future requirements:

- `remote_directory` remains required in a hand-written config. Only the optional setup wizard resolves a default from the remote home.
- Uploads may create their destination. `doctor` is optional and only checks an existing directory.
- SSH session detection is a process/socket heuristic, not an authenticated connection registry. It is not guaranteed for multiplexing, jump hosts or IDE-managed connections.
- The upload queue is unbounded, clipboard polling can miss rapid changes, and clipboard compare/write is not atomic.
- Foreground handoff drains uploads; background stop/restart may interrupt them.
- Failed images and remote uploads have no automatic retention policy. Interrupted transfers may leave partial remote files.

The original source import came from a local `codex-shot` prototype. Obsolete folder watching, Xnip-only filtering, backups and precompiled binaries were excluded. Do not restore personal paths, credentials or obsolete source filters when extending this toolkit.
